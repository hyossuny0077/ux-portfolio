04 — Supporting Work

이해관계자별 요구 — 페르소나 자료 기준

시니어 (76세 여성 · 83세 남성)

자녀에게 짐이 되고 싶지 않지만 혼자 있을 때 아프거나 사고가 날까 걱정한다. 돌봄의 대상이 아니라 든든한 가장으로 남고 싶어 하고, 노안으로 글 읽기가 불편해 글보다 말이 편하다.

보호자 (48세 여성 · 54세 남성)

평일엔 통화가 어려워 응급 상황이 생겨도 자신이 모를까 걱정한다. 활동 변화 중심의 자동 리포트, 다수 보호자 등록, 연락이 닿지 않을 때의 응급기관 연동을 원하며 참견으로 느껴지는 것은 경계한다.

기관 관리자 (42세 남성)

응급 상황과 단순 기기 오류를 한눈에 구분하지 못해 즉시 개입할 대상을 고르는 데 행정력이 든다. 시스템 데이터와 현장 상황이 어긋나면 책임이 관리자에게 몰리는 점을 부담스러워 한다.

응급관리요원 (55세 여성)

혼자 100명 이상을 관리하며, 비화재보로 소방차가 출동하면 구청 보고와 사유서 작성 부담이 크다. 119 신고 전에 직접 전화·방문으로 확인하려는 성향이 강하다.

“응급을 놓치면 안 된다”는 보호자·시니어의 불안과 “오신고는 줄여야 한다”는 현장의 부담이 서로 다른 방향을 가리킨다. 위험 알림의 15초 확인·취소 정책은 이 두 요구 사이에서 결정한 지점이다.

02 · 복약 등록 — 통합 입력에서 단계형으로

내가 한 것
시간대별 3화면 분리, 겹치지 않는 설정 범위 구조, 미래 칸 입력 차단, 예외 케이스 정리
팀과 함께한 것
예외 정리는 개발팀의 질문에서 시작했고, 시간 범위의 기준(아침 4~10시 등)은 기획본부가 잡았다
버린 안
한 화면에 세 시간대를 모두 두는 방식 — 글씨가 작아져 어르신이 보기 어려워서
결정 근거
어르신이 숫자를 직접 입력하기 어려워 선택식으로 바꾸고 시간대마다 화면을 나눔. 범위가 겹치지 않아 어떤 값을 골라도 아침 → 점심 → 저녁 순서가 유지된다

03 · 위험 알림 — 같은 모양의 팝업에서 한눈에 긴급한 전체 화면으로

  • — 유지한 것 — 119 연결 전 15초 확인과 [취소하기]로 오신고를 막는 흐름은 그대로 두고, 안내문을 4줄에서 2줄로 줄이고 “취소해 주세요” 말투로 부드럽게 바꿈
내가 한 것
알림 3등급 체계와 누적 규칙, 119 15초 확인 창, 취소 방법 3가지(화면·물리 버튼·음성), 물리 버튼 충돌·재부팅 예외 설계
팀이 정한 것
위험 대응 기준(누가 먼저 움직이는가). 이를 알림 명세와 화면에 반영했다
내가 직접 판단한 것
응급안전서비스 5차 기준의 기초만 기준으로 삼고, 그 위에 얹는 상세 규칙
결정 근거
119는 바로 신고하지 않고 15초 확인 창을 둠 — 놓침과 오작동 사이의 균형. 응급은 버튼 충돌·볼륨·알림 순서에서 모두 우선

컴포넌트 & 디자인 시스템

헤더, 버튼, 알림 토스트, 입력 스테퍼 등 반복 요소는 공통 컴포넌트로 운영했다. 화면은 1280px 기준에 상하좌우 30px 마진(콘텐츠 영역 1220px), 모서리는 20px을 기본 단위로 두었다. 폰트는 Pretendard(행간 1.45)이고, 버튼은 의미별 색(확인 Green · 취소/비상 Red · 주의 Orange · 정보 Blue · 브랜드 Purple · 비활성 Gray)으로 구분하며, 그림자는 Level 0~4 다섯 단계로 정의했다.

  • NOVA Green #01BB4B
  • Sub Green #C5E2C5
  • System Red #FF525A
  • System Orange #FF9B20
  • System Yellow #FFD335
  • System Blue #35C6FF
  • Text Primary #191919

컴포넌트는 헤더 4종(기본 · 알림 · 이전 · 이전+홈), 팝업, 토스트(5초 뒤 사라짐), 로딩, 스위치, 체크박스, 마이크·볼륨·배터리 상태 아이콘, 숫자 키패드, 한글·영문·특수문자 키보드, 미디어 컨트롤 눌림 상태까지 상태별로 정의했다. 인증번호 입력은 6칸 박스의 기본 · 입력 중 · 완료 · 오류 · 시간 초과 상태를, 버튼은 Medium/Small 두 크기에 Default · Press · Disabled 상태를 갖는다.

상단 헤더는 화면 맥락에 따라 바뀐다. 홈에서는 기본, 알림이 오면 알림 아이콘이 생기고, 복약·일정 등록 중에는 “이전”, 그 밖의 앱에서는 “홈으로” 버튼이 붙는다.

접근성 & 고령 친화 설계

  • — 큰 타이포그래피와 고대비 컬러 — 긴급 알림은 전체 화면 색상 블록으로 처리
  • — 터치 영역을 넓게 — 버튼은 손가락 오조작을 고려한 크기로 배치
  • — 음성 상태를 항상 시각으로도 병행 표기 — 듣는 중/생각 중/말하는 중을 눈 모양으로 구분

QA 사례 1

응급 중 알림 처리 규칙 충돌

발견 —
화재·119를 물리 [취소]로 끌 때 “예외 없이 알림을 모두 닫는다”와 “쌓인 알림은 응급이 끝난 뒤 다시 보인다” 두 규칙이 서로 부딪혔다.
수정 —
응급만 끄고 쌓인 알림은 다시 보이게 규칙을 하나로 정했다.
결과 —
복약이 ✗(안 먹음)로 잘못 기록되는 경우가 없어졌다.

QA 사례 2

누락된 응답 키워드

발견 —
안부확인 응답 키워드에 “안 괜찮아 · 119 불러줘”가 빠져 있었다. 위험알림·홈스테이션 명세에는 응급으로 처리한다고 적혀 있는데 알림 명세만 누락이었다.
수정 —
알림 명세에 키워드를 추가했다 (2026-10-29).
결과 —
세 문서가 같은 규칙을 가리킨다.
